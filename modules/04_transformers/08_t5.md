## What is T5?

T5 stands for **Text-to-Text Transfer Transformer**. Built by Google in 2019.

The core idea of T5 is elegantly simple:

> **Every NLP task is reframed as: take some text in → produce some text out.**

This sounds obvious, but it's a big shift. Before T5, different tasks needed different model architectures. T5 uses one architecture for everything.

> **C# analogy:** T5 is like a generic `Func<string, string>` that handles every NLP task. Before T5, you had `ClassifyText()`, `TranslateText()`, `SummarizeText()` as separate methods. T5 is one method that does all of them.

## The Text-to-Text Framework

Every task gets a **task prefix** in the input text:

```
┌──────────────────────────────────────────────────────────────────┐
│  Task              │  Input to T5                     │  Output   │
├──────────────────────────────────────────────────────────────────┤
│  Translation       │  "translate English to German:   │ "Das Haus │
│                    │   The house is red"               │  ist rot" │
├──────────────────────────────────────────────────────────────────┤
│  Summarization     │  "summarize: The meeting covered  │ "Budget   │
│                    │   budget planning and hiring..."  │  discussed"│
├──────────────────────────────────────────────────────────────────┤
│  Sentiment         │  "sentiment: I love this movie"  │ "positive"│
├──────────────────────────────────────────────────────────────────┤
│  Q&A               │  "question: What is the capital?  │ "Paris"   │
│                    │   context: France... Paris is..." │           │
├──────────────────────────────────────────────────────────────────┤
│  Grammar fix       │  "grammar: She go to school"     │ "She goes │
│                    │                                   │  to school"│
└──────────────────────────────────────────────────────────────────┘
```

The model learns to read the prefix and switch behavior accordingly. No separate heads, no separate models.

## Architecture: Encoder + Decoder

T5 uses the **full original transformer** — both encoder AND decoder:

```
┌─────────────────────────────────────────────────────────┐
│                     T5 Architecture                      │
│                                                          │
│  Input text                        Output text           │
│  "translate to German:             "Das Haus ist rot"   │
│   The house is red"                                      │
│       │                                    ↑             │
│       ▼                                    │             │
│  ┌──────────┐    Context vectors    ┌──────────┐         │
│  │          │ ─────────────────────▶│          │         │
│  │ Encoder  │                       │ Decoder  │         │
│  │          │                       │          │         │
│  │ (reads   │                       │(generates│         │
│  │  input   │                       │  output  │         │
│  │  fully)  │                       │ token by │         │
│  │          │                       │  token)  │         │
│  └──────────┘                       └──────────┘         │
└─────────────────────────────────────────────────────────┘
```

- **Encoder** reads the entire input and builds a rich understanding vector
- **Decoder** uses that understanding to generate output one token at a time
- The decoder attends to the encoder output via **cross-attention** (same as the original 2017 transformer)

> **C# analogy:** Encoder = parsing your input XML into an object. Decoder = serializing that object into JSON output. Different representations, same underlying data.

## T5 vs BERT vs GPT — Three Shapes of Transformer

```
                    BERT              GPT               T5
                (Encoder Only)   (Decoder Only)  (Encoder + Decoder)

Purpose:        Understand        Generate         Transform
                text              text             text → text

Direction:      Bidirectional     Left to right    Encoder: both ways
                                                   Decoder: left to right

Best for:       Classification,   Text completion,  Translation,
                Q&A, NER          chatbots, story   Summarization,
                                  writing           Q&A (with context)

Input:          Sequence          Previous tokens   Source text + prefix
Output:         Vectors per       Next token        Target sequence
                token             (greedy/sample)

Can classify?   Yes (via [CLS])   Yes (but awkward) Yes (via text output)
Can generate?   No                Yes               Yes

Creator:        Google 2018       OpenAI 2018-2023  Google 2019
```

## The C4 Dataset (Used to Train T5)

T5 was pre-trained on a massive dataset called **C4**: **Colossal Clean Crawled Corpus**.

See `modules/06_training_finetuning/07_training_datasets.md` for full details on C4.

Quick summary:
- 750GB of clean English text scraped from the internet (Common Crawl)
- Heavily filtered: removed non-English, removed boilerplate, removed duplicate content
- T5 saw so much text that it learned general language patterns before any fine-tuning

## Relative Position Encoding (T5 Innovation)

Standard transformers use fixed positional embeddings (lesson 04). T5 uses a simpler approach called **relative position bias**.

Instead of saying "token at position 5", T5 learns a bias that says "these two tokens are 3 apart". The exact position matters less than the relative distance.

```
Absolute (BERT/GPT): "Word at position 5"
                      Position 1: [PE1]
                      Position 5: [PE5]  ← fixed vectors

Relative (T5):        "Word is 4 positions after the other word"
                      Distance 4 → learned bias added to attention score
```

Benefit: T5 generalizes better to sequences longer than it was trained on.

## Pre-training Objective: Span Corruption

Unlike BERT (single word masking), T5 masks **spans** (multiple consecutive words) and replaces them with a single sentinel token:

```
Original:     "The quick brown fox jumps over the lazy dog"

Masked spans: "The quick <X> jumps over <Y> dog"
               (masked "brown fox")  (masked "the lazy")

Target:        "<X> brown fox <Y> the lazy"

Model must output all the masked spans, in order.
```

This is harder than BERT's single-word masking and forces the model to generate coherent spans.

## When to Use T5 vs BERT vs GPT

```
Your task needs...          → Use
─────────────────────────────────────────────────────
Classify a sentence         → BERT (or T5 with prefix)
Find answer in a document   → BERT
Translate text              → T5
Summarize a document        → T5
Complete a sentence         → GPT
Chat / conversation         → GPT
Multi-task in one model     → T5
```

## Visual: T5 Processing a Translation Task

```
Step 1: You provide input
  "translate English to French: The sky is blue"
         │
         ▼
Step 2: Encoder reads entire input (bidirectionally)
  ┌────────────────────────────────────────────────────┐
  │  [translate] [English] [to] [French] [:] [The]    │
  │  [sky] [is] [blue]                                 │
  │           ↕ attends to all tokens ↕               │
  │  Encoder output: context vector for full input     │
  └────────────────────────────────────────────────────┘
         │
         ▼
Step 3: Decoder generates output one token at a time
  Decoder step 1: attends to encoder + sees <start>  → "Le"
  Decoder step 2: attends to encoder + sees "Le"     → "ciel"
  Decoder step 3: attends to encoder + sees "Le ciel" → "est"
  Decoder step 4: attends to encoder + "Le ciel est"  → "bleu"
  Decoder step 5: attends to encoder + full output    → <end>

Result: "Le ciel est bleu"
```

## Quiz Questions

**Q1:** What does "text-to-text" mean in T5?  
→ Every NLP task is framed as: input text → output text. Translation, classification, Q&A all use the same format.

**Q2:** What is the task prefix in T5?  
→ A short string prepended to the input that tells the model what task to perform. Example: `"summarize:"`, `"translate English to German:"`.

**Q3:** T5 uses encoder + decoder. What does each part do?  
→ Encoder reads and understands the input. Decoder generates the output token by token using cross-attention to the encoder.

**Q4:** What dataset was T5 trained on?  
→ C4 — Colossal Clean Crawled Corpus. 750GB of cleaned English text from the internet.

**Q5:** What is Flan-T5?  
→ T5 fine-tuned on 1800+ NLP tasks with instruction format. Better at following instructions out of the box.

**Q6:** How is T5's masking different from BERT's masking?  
→ BERT masks single tokens. T5 masks spans (multiple consecutive words) and replaces them with sentinel tokens.

---

## Key Takeaways

- T5 = encoder-decoder transformer. Every task = text in, text out.
- Task prefix tells the model what to do: `"summarize:"`, `"translate:"`, etc.
- Uses full transformer (encoder reads input, decoder generates output).
- Pre-trained on C4 dataset (750GB cleaned web text).
- Span corruption pre-training: masks consecutive word groups, not just single tokens.
- Best for: translation, summarization, Q&A with source text, multi-task scenarios.
- Flan-T5 = instruction-tuned T5, ready for diverse tasks out of the box.
