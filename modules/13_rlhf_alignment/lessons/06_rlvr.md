# Lesson 06: RLVR — Reinforcement Learning with Verifiable Rewards

## Glossary (Read This First!)

Every term used in this lesson is defined here.
Do not skip this section.

| Term | Plain English Definition | C# Analogy |
|------|--------------------------|------------|
| **RLVR** | Reinforcement Learning with Verifiable Rewards. Train a model using rewards that come from automatically checking if the answer is correct — no human labelers needed. | Like running a unit test suite: pass = 1, fail = 0. No human reviewer required. |
| **Verifiable reward** | A reward signal you can compute automatically. Math: check if final number matches. Code: run the test suite. Logic puzzles: check rules are satisfied. | Like a CI/CD pipeline that auto-grades a build — green = pass, red = fail. |
| **Reward hacking** | When a model learns to game the reward signal without actually improving. Example: rewarded for "sounding confident" → always uses confident language even when wrong. | Like a developer who only adds comments to satisfy the linter, without actually writing useful comments. |
| **Binary reward** | Reward of 1 (correct) or 0 (wrong). Simplest form of verifiable reward. | Like a bool — true/false, no partial credit. |
| **Format reward** | Extra reward for following a required output format (e.g., wrapping reasoning in `<think>` tags). Encourages the model to show its work. | Like style guidelines in a code review: content must be correct AND formatted correctly. |
| **Rollout** | One complete response generated by the model for a given prompt. RLVR scores each rollout. | Like one build artifact produced by CI — you score each build. |
| **Policy** | The LLM itself. In RL terms, the policy takes a state (the prompt) and produces an action (the response). | Like a strategy pattern: given an input, it produces an output. |
| **Reward model** | In RLHF, a learned model that predicts human preference scores. In RLVR, this is replaced by an automated checker. | In RLHF: a learned scoring service. In RLVR: a deterministic unit test runner. |
| **RLHF** | Reinforcement Learning from Human Feedback. Reward comes from human preference labels. Expensive and slow. (Covered in Lesson 01.) | Like hiring human QA testers to score every output. |
| **DeepSeek-R1** | The model released by DeepSeek in January 2025 that proved RLVR alone (no SFT warmup) can produce strong reasoning. It used GRPO + math/code verifiable rewards. | Like shipping a product trained entirely on automated test results, no human sign-off. |

## The Problem with RLHF Reward Models

In Lesson 01, you learned the 3-phase RLHF pipeline:
1. SFT: fine-tune on demonstration data
2. Reward model: learn to predict human preferences
3. PPO: optimize against the reward model

The reward model is trained on human labels — but humans are:
- **Expensive:** Labeling 1 million responses costs millions of dollars
- **Slow:** You need human feedback to improve the model
- **Inconsistent:** Two humans often disagree on which response is better
- **Gameable:** The model learns to write responses that *look* good to humans, not responses that *are* good

This last problem is called **reward hacking**. The model optimizes for the score, not for actually being correct.

```
RLHF reward hacking example:
  Prompt: "What is 2 + 2?"
  
  Response A: "The answer is 4."               Score: 7/10
  Response B: "Great question! After careful   Score: 9/10  <-- HIGHER
               consideration of all factors,
               I believe the answer is 4."
  
  The model learns: be verbose and confident = higher score
  Even though A is strictly better.
```

---

## RLVR: Replace the Reward Model with a Checker

The key insight of RLVR:

> For tasks where the answer can be **verified automatically**, you don't need a reward model. You don't need humans. You just need a checker.

```
RLHF:
  Prompt --> Model --> Response --> Human labels it --> Reward signal --> Update model
                                        ^
                                        |
                                   EXPENSIVE, SLOW

RLVR:
  Prompt --> Model --> Response --> Checker verifies --> Reward signal --> Update model
                                        ^
                                        |
                                   FREE, INSTANT, UNCHEATEABLE
```

The checker is deterministic — the model cannot game it.

---

## Where RLVR Works

RLVR requires tasks where correctness can be verified automatically.

| Domain | How to verify | Reward |
|--------|--------------|--------|
| **Math** | Extract final number, compare to known answer | 1.0 if exact match, 0.0 if wrong |
| **Code** | Run test suite against generated code | pass_rate = tests_passed / total_tests |
| **Logic puzzles** | Check if constraints are satisfied | 1.0 if all constraints hold |
| **Factual QA** | Check against a database of known facts | 1.0 if fact matches |
| **Formal proofs** | Run a proof verifier (Lean, Coq) | 1.0 if proof is valid |

RLVR does NOT work for:
- Open-ended creative writing (no "correct" answer)
- Subjective tasks (helpfulness, tone, style)
- General conversation (hard to verify)

For those domains, you still need RLHF with human labels.

## The Reward Function in Practice

A typical RLVR reward function combines two signals:

```
total_reward = correctness_reward + format_reward

correctness_reward:
  -- 1.0 if the answer is correct
  -- 0.0 if the answer is wrong
  -- (sometimes partial credit, e.g. 0.5 for correct method but arithmetic error)

format_reward:
  -- small bonus (0.1 to 0.2) if the model used the required format
  -- e.g. wrapped reasoning in <think>...</think> tags
  -- e.g. put the final answer in \boxed{...}
```

**Why format reward?**
It encourages the model to "show its work" — to write out reasoning steps before giving the answer.
This is how extended chain-of-thought emerges from RLVR training.

```
Prompt:   "What is 15% of 80?"

Bad response (no thinking):
  "12"
  --> correctness_reward = 1.0, format_reward = 0.0, total = 1.0

Good response (with thinking):
  "<think>
  15% means 15/100.
  15/100 × 80 = 0.15 × 80 = 12
  </think>
  12"
  --> correctness_reward = 1.0, format_reward = 0.2, total = 1.2

The model learns: showing thinking = higher total reward
```

## DeepSeek-R1: The Proof That RLVR Works

DeepSeek-R1 (January 2025) was the first major open-weight model trained with RLVR.

Key facts:
- Used ONLY math and code RLVR — no human preference labels
- The DeepSeek-R1-Zero variant skipped SFT entirely — pure RLVR from a pretrained base
- Results: matched OpenAI o1 on math benchmarks (AIME, AMC)
- The model spontaneously developed extended reasoning — sometimes thinking for thousands of tokens
- DeepSeek called this the **"aha moment"**: the model learned to backtrack, verify, and reconsider on its own

```
DeepSeek-R1 training:
  Base model (DeepSeek-V3)
       |
       | RLVR (no SFT, no human labels)
       | Reward: math answer correct? code tests pass?
       v
  R1-Zero: strong math/code reasoning
       |
       | Optional: small SFT warmup for better format
       v
  R1: production model, matches OpenAI o1
```

The lesson: **for verifiable domains, RLVR is more powerful than RLHF** because:
1. No reward hacking (automated checker can't be gamed)
2. Infinite scale (run millions of math problems automatically)
3. No human bottleneck

## RLVR vs RLHF: Side-by-Side

| Aspect | RLHF | RLVR |
|--------|------|------|
| Reward source | Human preference labels | Automated correctness checker |
| Cost | Very expensive | Free |
| Speed | Slow (wait for humans) | Instant |
| Reward hacking risk | High | Low (checker is deterministic) |
| Domains | All tasks (subjective too) | Verifiable tasks only (math, code) |
| Human labels needed | Yes | No |
| Used by | ChatGPT, Claude (early training) | DeepSeek-R1, Qwen3, Llama4 reasoning |
| Reward model | Learned neural network | Hard-coded rule / test runner |

## C# Analogy: Unit Tests as the Training Signal

In .NET development, you write code and run unit tests to check if it works.
RLVR does the same thing — but the "developer" is the LLM, and it learns from the test results.

```csharp
// C# unit test (this IS the reward function in RLVR for code tasks)
[Test]
public void TestGeneratedCode()
{
    // Model generated this function
    var result = ModelGeneratedCode.Add(2, 3);
    
    // This assertion IS the reward signal
    // Pass -> reward = 1.0
    // Fail -> reward = 0.0
    Assert.AreEqual(5, result);
}
```

The LLM generates code, the test runner checks it, the pass/fail IS the reward.
No human reviewer. No reward model. Just a deterministic checker.

---

## Key Takeaways

1. **RLVR replaces the reward model** with an automated checker for verifiable tasks
2. **No human labels needed** — reward comes from running tests or checking answers
3. **No reward hacking** — the checker is deterministic, can't be gamed
4. **Format reward** encourages the model to show reasoning, which makes it more accurate
5. **DeepSeek-R1 proved** that RLVR alone (no SFT) produces frontier-level reasoning
6. **Works for:** math, code, logic, formal proofs — NOT for open-ended tasks
