# Lesson 02: BM25 — Smarter Keyword Ranking

## Glossary (Read This First!)

| Term | Plain English Definition |
|------|--------------------------|
| **BM25** | Best Match 25. A ranking formula that improves on TF-IDF. The "25" refers to the 25th iteration of research refinements. Industry standard for keyword search. |
| **Saturation** | In BM25, adding more copies of a word gives diminishing returns. The 100th "cat" in a document adds almost nothing to the score. |
| **Document length normalization** | Penalizing long documents. A word appearing 5 times in a 50-word doc is more significant than 5 times in a 5000-word doc. |
| **k1 parameter** | Controls term frequency saturation. Typical value: 1.2 to 2.0. Higher k1 = more reward for repeated words. |
| **b parameter** | Controls document length normalization. Range 0 to 1. b=1 = full normalization. b=0 = no normalization. Default: 0.75. |
| **avgdl** | Average document length across the corpus. Used in the BM25 length normalization formula. |
| **IDF (BM25 version)** | Slightly different from TF-IDF's IDF. Uses a smoothed formula to avoid negative scores. |
| **Inverted index** | A lookup table: word → list of documents containing that word. Makes retrieval fast (no need to scan all documents). |
| **rank-bm25** | Python library that implements BM25. Install with `pip install rank-bm25`. |

## Part 1: What Is Wrong With TF-IDF?

TF-IDF has two problems that BM25 fixes.

### Problem 1: No Saturation

In TF-IDF, if a word appears 100 times in a document instead of 10 times,
the score goes up 10x. That is too much reward for repetition.

```
TF-IDF: word appears 10 times → score 1.0
        word appears 100 times → score 10.0  (10x more!)
        word appears 1000 times → score 100.0 (100x more!)

BM25:   word appears 10 times → score 1.0
        word appears 100 times → score 1.4   (only 40% more)
        word appears 1000 times → score 1.5  (almost no gain)
```

BM25 uses saturation so repeated words give diminishing returns.

### Problem 2: No Length Normalization

In TF-IDF, a 10,000-word document that mentions "cat" 50 times beats a
100-word document that mentions "cat" 10 times — even though the short
document is much more focused on cats.

```
Doc A (100 words):   "cat" appears 10 times → TF = 0.10
Doc B (10000 words): "cat" appears 50 times → TF = 0.005

Wait -- TF already handles this! TF = count / total_words.
But TF-IDF's raw count approach does not normalize well at extremes.
BM25 uses a more principled normalization formula.
```

BM25 normalizes scores relative to average document length in the corpus.

## Part 2: The BM25 Formula

```
+------------------------------------------------------------------+
|  BM25 SCORE FORMULA                                              |
+------------------------------------------------------------------+
|                                                                  |
|             IDF(q) * TF(q, d) * (k1 + 1)                        |
|  score =  ─────────────────────────────────────────────         |
|             TF(q, d) + k1 * (1 - b + b * |d| / avgdl)           |
|                                                                  |
|  Where:                                                          |
|    q     = query term (one word from the query)                  |
|    d     = document being scored                                 |
|    TF    = count of q in d  (raw count, not divided by length)  |
|    IDF   = log((N - df + 0.5) / (df + 0.5) + 1)                 |
|    k1    = saturation parameter (default 1.5)                    |
|    b     = length normalization parameter (default 0.75)         |
|    |d|   = length of document d in tokens                        |
|    avgdl = average document length across corpus                 |
|    N     = total number of documents                             |
|    df    = number of documents containing term q                 |
|                                                                  |
+------------------------------------------------------------------+
```

Do not worry about memorizing this formula.
The key ideas are:

1. **Numerator** — rewards high TF (word appears a lot in this doc)
2. **Denominator** — penalizes long documents and caps TF saturation
3. **IDF part** — still rewards rare words (same principle as TF-IDF)

## Part 4: The k1 and b Parameters

### k1 — Saturation Control

```
+--------------------------------------------+
|  k1 effect on score saturation              |
+--------------------------------------------+
|  k1 = 0.0  |  TF completely ignored         |
|  k1 = 1.2  |  Quick saturation (standard)   |
|  k1 = 1.5  |  Moderate saturation (default) |
|  k1 = 2.0  |  Slow saturation               |
|  k1 = 100  |  Behaves like TF-IDF (no sat.) |
+--------------------------------------------+
```

Rule of thumb: keep k1 between 1.2 and 2.0. Most implementations default to 1.5.

### b — Length Normalization

```
+-----------------------------------------------+
|  b effect on length normalization              |
+-----------------------------------------------+
|  b = 0.0  |  Ignore document length entirely   |
|  b = 0.75 |  Standard normalization (default)  |
|  b = 1.0  |  Full normalization (strong)        |
+-----------------------------------------------+
```

- b = 0 is good when all documents are roughly the same length
- b = 0.75 is the best default for most use cases
- b = 1.0 heavily penalizes long documents

C# analogy:
```csharp
// k1 and b are like configuring a SQL full-text search ranking:
// ALTER FULLTEXT INDEX SET CHANGE_TRACKING AUTO;
// -- The underlying scoring engine has similar tuning parameters
// -- but SQL Server hides them. BM25 exposes them directly.
```

```

|  Saturation               | No            | Yes (k1 parameter)   |

|  IDF formula              | log(N/df)     | Smoothed log formula  |

+------------------------------------------------------------------+
```

**BM25 is the default ranking algorithm in Elasticsearch and Apache Solr.**
If you have ever used Google, Bing, or enterprise search — you have used BM25.

## Part 6: The Inverted Index (How BM25 Stays Fast)

Without an index, searching 1 million documents means reading all 1 million documents.
BM25 uses an **inverted index** to search in milliseconds.

```
+------------------------------------------------------------------+
|  INVERTED INDEX                                                  |
+------------------------------------------------------------------+
|                                                                  |
|  Normal (forward) index:                                         |
|    Doc 1 → ["cat", "sat", "mat"]                                 |
|    Doc 2 → ["dog", "ran", "park"]                                |
|    Doc 3 → ["cat", "dog", "played"]                              |
|                                                                  |
|  Inverted index (word → document list):                          |
|    "cat"    → [Doc 1 (count=1), Doc 3 (count=1)]                |
|    "dog"    → [Doc 2 (count=1), Doc 3 (count=1)]                |
|    "sat"    → [Doc 1 (count=1)]                                  |
|    "ran"    → [Doc 2 (count=1)]                                  |
|    "park"   → [Doc 2 (count=1)]                                  |
|    "played" → [Doc 3 (count=1)]                                  |
|    "mat"    → [Doc 1 (count=1)]                                  |
|                                                                  |
|  Query "cat dog":                                                |
|    Look up "cat" → Doc 1, Doc 3                                  |
|    Look up "dog" → Doc 2, Doc 3                                  |
|    Union → Doc 1, Doc 2, Doc 3 (all candidates)                  |
|    Score each → Doc 3 wins (has both words)                      |
|                                                                  |
|  Time: O(words_in_query) not O(corpus_size)                      |
|                                                                  |
+------------------------------------------------------------------+
```

C# analogy:
```csharp
// Dictionary<string, List<(int docId, int count)>>
var invertedIndex = new Dictionary<string, List<(int, int)>>();
invertedIndex["cat"] = new() { (docId: 1, count: 1), (docId: 3, count: 1) };

// Query: look up each word, union results, score and rank.
// Same logic as BM25, just with a simpler scoring formula.
```

## Part 7: BM25 in Python (rank-bm25 library)

```python
from rank_bm25 import BM25Okapi

# Corpus: list of tokenized documents
# Each document is a list of words (already split)
corpus = [
    ["cat", "sat", "mat"],
    ["dog", "ran", "park"],
    ["cat", "dog", "played"],
]

# Build the BM25 index (this is the "indexing" phase)
bm25 = BM25Okapi(corpus)

# Query (also tokenized)
query = ["cat", "dog"]

# Get scores for all documents
scores = bm25.get_scores(query)      # [0.93, 0.46, 1.39]
# Higher score = more relevant

# Get top N documents
top_n = bm25.get_top_n(query, corpus, n=2)
# Returns: [["cat", "dog", "played"], ["cat", "sat", "mat"]]
```

The `BM25Okapi` class uses k1=1.5 and b=0.75 by default.
`Okapi` refers to the Okapi BM25 variant — the most widely used version.

**Q2.** What does the k1 parameter control?

**Q3.** A word appears 10 times in Doc A and 100 times in Doc B. In BM25 with k1=1.5, is Doc B's score 10x higher? Why or why not?

**Q4.** What is b=0 equivalent to in terms of document length?

## Answers

**A1.** (1) No saturation — repeated words get unbounded TF credit. (2) No proper length normalization — long docs get unfair advantage.

**A2.** k1 controls how quickly the term frequency reward saturates. High k1 = more reward for repetition. Low k1 = less reward.

**A3.** No. BM25 saturates — after ~10 occurrences, extra copies barely increase the score. Doc B gets maybe 40% more, not 10x.

**A4.** b=0 means document length is completely ignored in scoring. Every document is treated as if it has the average length.

**A5.** Elasticsearch (and Apache Solr) use BM25 as the default ranking algorithm.

**A6.** Inverted index — maps each word to the list of documents containing it. Lets BM25 skip documents that don't contain any query words.
